#+title: spectreshell モジュール API (emacs-module 境界)

~libspectreshell.so~ が ~emacs_module_init~ で defalias する Elisp 関数と、
その戻り値の plist 形式を記録する。[[file:design.org][design.org]] の
「モジュール API (案)」を Phase 2 の実装に合わせて具体化したもの。
Phase 3 (spectreshell.el) 以降はこのドキュメントを参照する。

* 公開関数

| 関数 | 引数 | 戻り値 |
|------+------+--------|
| ~(spectreshell--create ROWS COLS)~ | ROWS, COLS: 1〜65535 の整数 | TERM (user-ptr, finalizer 付き) |
| ~(spectreshell--feed TERM BYTES)~ | TERM: user-ptr、BYTES: unibyte 文字列 | 更新情報 plist |
| ~(spectreshell--resize TERM ROWS COLS)~ | TERM、ROWS/COLS: 1〜65535 の整数 | 更新情報 plist (全行 dirty) |
| ~(spectreshell--flush TERM)~ | TERM | 更新情報 plist |
| ~(spectreshell--encode-key TERM KEY MODIFIERS)~ | TERM、KEY、MODIFIERS | unibyte 文字列 or nil |
| ~(spectreshell--encode-paste TERM TEXT)~ | TERM、TEXT: 文字列 | unibyte 文字列 |
| ~(spectreshell--encode-mouse TERM BUTTON ACTION ROW COL MODIFIERS)~ | TERM、BUTTON、ACTION、ROW/COL: 整数、MODIFIERS | unibyte 文字列 or nil |
| ~(spectreshell--set-color-scheme TERM SCHEME)~ | TERM、SCHEME: ~dark~ / ~light~ | unibyte 文字列 or nil |
| ~(spectreshell--set-colors TERM FG BG PALETTE)~ | TERM、FG/BG: 色 or nil、PALETTE: 色 or nil の 16 要素のリスト | nil (副作用のみ) |
| ~(spectreshell--release TERM)~ | TERM | nil (副作用のみ) |

TERM は ~spectreshell--create~ が返す user-ptr。他のモジュールの
user-ptr や整数など、うちの Term でない値を渡すと
~wrong-type-argument~ が signal される。 ~spectreshell--release~ 済みの
TERM に ~--feed~ / ~--resize~ / ~--flush~ / ~--encode-key~ / ~--encode-paste~ /
~--encode-mouse~ / ~--set-color-scheme~ / ~--set-colors~ を呼ぶと ~spectreshell-terminal-released~ (~error~ の
子コンディション) が signal される。 ~--release~ 自体は二重に呼んでも
安全 (2回目は no-op)。

ROWS/COLS に整数以外を渡すと Emacs 本体の型検査により
~wrong-type-argument~ が、範囲外 (0 以下または 65536 以上) だと
~args-out-of-range~ が signal される。

* ~--feed~ / ~--resize~ / ~--flush~ の戻り値 plist

#+begin_src elisp
(:dirty ((ROW TEXT SPANS CELLS) ...)
 :scrolled-off ((TEXT SPANS CELLS) ...)
 :styles ((ID . STYLE-PLIST) ...)
 :styles-reset t-or-omitted
 :cursor (ROW . COL)
 :cursor-index INDEX
 :cursor-visible t-or-nil
 :responses "raw-bytes-or-omitted"
 :relay ((SYMBOL ARGS...) ...)
 :clipboard ((:op OP ...) ...)
 :focus-event t-or-omitted
 :alt-screen entered-or-left-or-omitted
 :title "title-or-omitted")
#+end_src

- *~:dirty~*: 変更のあった行。ROW は 0-origin の整数、TEXT は行の内容
  (下記「文字列の扱い」参照)、SPANS は下記のスタイル区間リスト、CELLS
  は下記の書記素ごとのセル数。
- *~:scrolled-off~*: 可視領域上端から流れ出て確定化すべき行。TEXT・
  SPANS・CELLS は ~:dirty~ と同じ。
- *~:styles~*: この update で *初めて使われた* スタイル ID とその内容。
  ID は端末ごとの通し番号で、一度送ったスタイルは二度と送らない。
  受け手は ID→スタイル (および ID→face) を覚えておく必要がある。
- *~:styles-reset~*: 真なら、それまでの ID をすべて捨てること
  (モジュールがテーブルを振り直した)。同じ update に画面全行が
  ~:dirty~ として載るので、捨てた直後に描き直せる。ID の種類が上限を
  超えたときだけ起きる。
- *~:cursor~* / *~:cursor-index~* / *~:cursor-visible~*: 常に含まれる。
  ROW/COL はどちらも 0-origin で、COL は *端末セル列* である点に注意
  (SPANS の START/END と違いコードポイントオフセットではない)。
  ~:cursor-index~ は同じ位置を「その行の TEXT 内のコードポイント
  オフセット」で表したもの。表示桁 (~move-to-column~) で解くと、
  ghostty が 2 セルと数えて Emacs の ~char-width~ が 1 を返す文字
  (単独の regional indicator など) でずれるので、カーソル位置は
  ~:cursor-index~ で解くこと。
- *~:responses~*: PTY に送り返すべき応答バイト列 (DA / DSR / DECRQM /
  kitty keyboard の問い合わせ等)。
  何もなければキーごと省略される。
- *~:relay~*: 子が外側の端末へ向けて出したもの。描画とは別に Elisp が
  外側の tty へ中継する。子が出した順に並び、何もなければキーごと
  省略される。
  - ~(notification TITLE BODY)~: OSC 777 (~notify;TITLE;BODY~) と、
    ConEmu 拡張でない OSC 9 (BODY のみ。TITLE は ~""~) の通知。どちらも
    子が送ったままのバイト列。
  - ~(progress STATE VALUE)~: OSC 9;4 の進捗。STATE は OSC 9;4 の番号
    (0 消去・1 設定・2 エラー・3 不定・4 一時停止) の整数、VALUE は
    0〜100 の整数か ~nil~ 。ghostty-vt の解釈どおり、0 と 3 の VALUE は
    常に ~nil~ で、1 の VALUE を省くと 0 になる。
  - ~(bell)~: BEL。OSC などの終端の BEL は含まない。
- *~:clipboard~*: 子のクリップボード操作の要求。子が出した順に並び、
  何もなければキーごと省略される。Elisp は feed の中では処理せず、後で
  順に処理する (design.org の判断 19)。各要素は ~:op~ で種類が分かる
  plist で、LOC は ~clipboard~ か ~primary~ (OSC 52 の ~p~ と ~s~ は
  ~primary~ 、それ以外は ~clipboard~)。
  - ~(:op write :loc LOC :text TEXT)~: 書き込み。TEXT は base64 を解いた
    バイト列 (unibyte。UTF-8 として解くのは受け手)。空の書き込みと
    base64 として不正な書き込みは載せない。
- *~:focus-event~*: 子がフォーカスの報告 (mode 1004) を有効にしている
  間は ~t~ 。無効ならキーごと省略される。
- *~:alt-screen~*: このバッチで alternate screen への出入りが
  あった場合のみ ~entered~ / ~left~ シンボルを持つ。変化なしならキー
  ごと省略される。
- *~:title~*: OSC 0/2 でタイトルが変更された場合のみ含まれる。

** 描画の保留 (mode 2026)

~--feed~ が mode 2026 (synchronized output) の中で終わると、戻り値は
~(:synchronized t :responses "raw-bytes-or-omitted" :relay ... :clipboard ... :focus-event ...)~
だけになる (~:relay~ ・ ~:clipboard~ ・ ~:focus-event~ は描画ではないので保留しない)。
保留した変更は、mode 2026 が閉じた ~--feed~ の戻り値にまとめて載る。
~--resize~ と ~--flush~ は mode 2026 を解除してから通常の plist を返す。
~--flush~ はアプリが mode 2026 を閉じないまま止まったときに使う。

** CELLS

TEXT の文字数と同じ長さの unibyte 文字列で、i バイト目は TEXT の
i 文字目から始まる書記素のセル数 (1 か 2)。書記素の 2 文字目以降は 0。
全文字が 1 (1 文字 1 セル) の行では ~nil~ 。

書記素の区切りとセル数は ghostty-vt のセルそのもので、mode 2027 の
有無で変わる (例: 国旗は有効なら ~"\2\0"~ 、無効なら ~"\2\2"~ )。
Emacs の ~char-width~ からは導けない (単独のコードポイントでも食い違う
ものがあり、ZWJ 列などは mode 2027 が無効でも 1 セルに複数の文字が入る)
ので、セル列と文字位置の対応はこれで解く。

** SPANS

#+begin_src elisp
((START END ID) ...)        ; ハイパーリンクなし
((START END ID . URI) ...)  ; OSC 8 のリンク区間
#+end_src

START/END は TEXT 内のコードポイントオフセット (Emacs の文字列
インデックスと一致、バイトオフセットでもセル幅でもない)。ID は
~:styles~ で送られたスタイル ID。装飾もリンクもない区間は SPANS に
現れない (「span が無い = 既定描画」)。

スタイルを plist ではなく ID で送るのは、1 行に数十区間が乗る出力
(git-delta の差分など) で、区間ごとに plist を作って face に変換する
コストが描画時間の大半を占めるため。ID なら受け手は face を 1 回だけ
作ってキャッシュできる。URI をスタイルに含めないのは、face と無関係
なうえ、URI ごとに ID が増えるとキャッシュが効かなくなるため。

STYLE-PLIST のキーはすべて値が既定 (装飾なし) の場合キーごと省略する:

| キー | 値 |
|------+----|
| ~:fg~ / ~:bg~ | パレット index (0〜255 の整数) または ~"#rrggbb"~ 文字列 (24bit色) |
| ~:bold~ / ~:italic~ / ~:faint~ / ~:strikethrough~ / ~:inverse~ / ~:invisible~ | ~t~ |
| ~:underline~ | ~t~ (single) / ~double~ / ~curly~ / ~dotted~ / ~dashed~ |

* ~--encode-key~ の KEY / MODIFIERS

- *KEY*: 印字可能な1文字は長さ1の文字列 (例 ~"a"~, ~"あ"~)。
  特殊キーはシンボル: ~up down left right home end prior next insert
  delete backspace tab return escape f1~ 〜 ~f12~ の各シンボル。
- *MODIFIERS*: シンボルのリスト。認識するのは ~ctrl~ ~alt~ ~shift~
  ~super~ の 4 つ。 ~alt~ は Emacs の meta に対応させる (呼び出し側で変換する)。
  未知のシンボルは無視される。
- DECCKM (カーソルキーモード) や kitty keyboard protocol、
  modifyOtherKeys など端末モードへの追従はモジュール内部の端末状態
  (TERM が保持) に従って自動的に行われる。
- KEY が空文字列/2文字以上の文字列、または未知のシンボルの場合は
  ~error~ を signal する。

戻り値は PTY に送る unibyte 文字列。何も送る必要がない場合 (例:
モディファイアキー単体など) は ~nil~ になる。

* ~--encode-paste~ の TEXT

TEXT は通常の (マルチバイト) Lisp 文字列。bracketed paste モードが
有効なら =ESC[200~...ESC[201~= で囲んで返す。無効なら中身をそのまま
返す。改行は端末に送る規約に合わせて ~\n~ → ~\r~ に正規化される
(ghostty-vt のペーストエンコーダの挙動)。戻り値は unibyte 文字列。

* ~--encode-mouse~ の BUTTON / ACTION / ROW / COL / MODIFIERS

ghostty-vt はマウスレポートのエンコーダを公開していないため、ghostty
本体 (~src/Surface.zig~ の ~mouseReport~) のボタン番号割り当てを
~--encode-key~ と同じ層 (モジュール内) に移植したもの。TERM が保持する
マウストラッキングモード (mode 9/1000/1002/1003) とフォーマット
(mode 1005/1006/1015、無指定なら x10) に自動的に追従する。

- *BUTTON*: ~nil~ (ボタンを押さない motion のみ)、整数 ~1~ / ~2~ / ~3~
  (それぞれ left/middle/right)、またはシンボル
  ~wheel-up~ / ~wheel-down~ / ~wheel-left~ / ~wheel-right~ のいずれか。
  それ以外の整数・シンボルは ~error~ を signal する。
- *ACTION*: シンボル ~press~ / ~release~ / ~motion~ のいずれか。
  それ以外は ~error~ を signal する。
- *ROW / COL*: 0-origin の整数の端末 *セル* 座標
  (~--encode-key~ の KEY と違い、印字可能文字ではなくクリック位置)。
  ~:cursor~ の ROW/COL と同じ単位で、バッファの文字オフセットではない:
  全角文字を含む行では表示桁 (~current-column~) から求めること。
  範囲外 (0 未満または 65536 以上) は ~args-out-of-range~ を signal する。
- *MODIFIERS*: ~--encode-key~ と同じシンボルのリストを受け取るが、
  ghostty のマウスレポートは ~ctrl~ / ~alt~ / ~shift~ しか表現できないため
  ~super~ は無視される (未知のシンボル同様、エラーにはしない)。

マウストラッキングが無効 (TERM がどの ~?100x~ モードも受け取っていない)
なら常に ~nil~ を返す。トラッキングが有効でも、現在のモードがその
BUTTON/ACTION の組み合わせを報告しない場合 (例: mode 1000 での motion、
mode 1002 でのボタンなし motion) も ~nil~ を返す。戻り値は PTY に送る
unibyte 文字列。

* ~--set-color-scheme~ の SCHEME

子の明暗の問い合わせ (=\e[?996n=) に答える値。TERM はこれを覚え、
=\e[?997;1n= (~dark~) / =\e[?997;2n= (~light~) で答える。一度も渡して
いなければ答えない。それ以外のシンボルは ~error~ を signal する。

戻り値は、子が mode 2031 を有効にしていて SCHEME が前回と違うときだけ、
子へ送る同じ形の通知 (unibyte 文字列)。それ以外は ~nil~ 。

* ~--set-colors~ の FG / BG / PALETTE

子の色の問い合わせに答える値。色は ~color-values~ と同じ 16bit の
~(R G B)~ (各 0〜65535)。TERM はこれを覚え、OSC 10 (FG) ・ OSC 11 (BG) ・
OSC 4 の 0〜15 (PALETTE) に Ghostty と同じく
=\e]N;rgb:RRRR/GGGG/BBBB= (OSC 4 は =\e]4;I;rgb:...=) を問い合わせと同じ
終端 (BEL / ST) で、 ~--feed~ の ~:responses~ に返す。 ~nil~ の色と、
一度も渡していない色には答えない。OSC 4 の 16〜255 は渡さなくても、描画と
同じ xterm の 256 色の値で答える。子による色の設定・リセットは答えに
効かない。

成分が範囲外のとき、色が 3 要素でないとき、PALETTE が 16 要素でないときは
~args-out-of-range~ を、整数でない成分は ~wrong-type-argument~ を signal
する。

* 文字列の扱い (unibyte / multibyte)

- *~--feed~ の BYTES*: 呼び出し側は unibyte 文字列で渡すこと。PTY
  からの生バイト列をそのまま ~copy_string_contents~ で読み出す。
  ERT (~spectreshell-module-test.el~) で実証したとおり、
  ~unibyte-string~ で作った 0x80 以上を含むバイト列は
  ~copy_string_contents~ → Zig 側バッファ → (~--encode-paste~ 経由で)
  ~make_unibyte_string~ という往復で1バイトも変化せず戻ってくる。
  一方、そのバイト列を実際に ~--feed~ で VT パーサに通すと、単独の
  0x80〜0xFF は妥当な UTF-8 として解釈できないため ghostty-vt 側で
  置換文字相当の表示になる (これは端末エミュレーションとして妥当な
  挙動であり、モジュール境界のバグではない)。
- *~:dirty~ / ~:scrolled-off~ の TEXT*: 画面上の文字列なので常に
  UTF-8 の multibyte Lisp 文字列 (~make_string~) として返す。
  セル 1 つは TEXT の 1 文字以上 (1 つの書記素) になり、対応は CELLS
  が表す。DEL (0x7F) は ECMA-48 どおり無視してセルに入れず、C1 制御
  (U+0080-U+009F) は U+FFFD に置き換えて返す。どちらも Emacs では
  ~^?~ ・ ~\205~ のように複数桁で描かれ、セル列と表示桁がずれるため。
- *~:dirty~ / ~:scrolled-off~ の CELLS*: 文字ではなく数の並びなので
  unibyte 文字列。
- *~:responses~*: DA/DSR 等の制御応答は unibyte 文字列
  (~make_unibyte_string~) として返す。
- *~:relay~ の文字列*: 外側の端末へ書くバイト列の材料なので unibyte
  文字列として返す。
- *~:clipboard~ の TEXT*: 子が書いたバイト列のままの unibyte 文字列。
- *~--encode-key~ / ~--encode-paste~ の戻り値*: PTY にそのまま書き込む
  前提のバイト列なので unibyte 文字列。

* エラー処理の実装メモ (実装者向け)

- Emacs 本体の env 関数 (~extract_integer~ / ~copy_string_contents~ 等)
  は型不一致のとき自前で non-local exit (~wrong-type-argument~ 等) を
  積む。Zig 側はこれを ~non_local_exit_check~ で検知したら追加の
  signal を呼ばずに即座にエラーとして伝播する (二重に signal すると
  未定義動作になるため)。
- TERM の型検証は ~type-of~ が ~user-ptr~ であることに加え、
  ~get_user_finalizer~ が本モジュールの finalizer 関数と一致するかで
  行う (user-ptr には Emacs 側の型タグ機構がないため)。
- ~--release~ は ~set_user_ptr~ で user-ptr の中身を ~NULL~ にすることで
  二重解放を安全にしている。GC 時の finalizer は data が ~NULL~ なら
  何もしない。
