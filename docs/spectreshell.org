spectreshell は eshell 向けの端末エミュレーション統合である。ghostty
の端末エミュレーションライブラリ ~ghostty-vt~ を Zig 製の Emacs
ダイナミックモジュールから使い、 ~ls --color~ の色付き出力・進捗表示・
less/vim のような alternate screen アプリの出力を eshell バッファ内で
正しく描画する。

本マニュアルは利用者向けの説明である。内部設計は同梱の
~docs/design.org~ を、モジュール境界の API 仕様は
~docs/module-api.org~ を参照。

* 概要

spectreshell が提供するのは次の 1 点に絞られている: eshell で外部
プロセスを実行したとき、色・カーソル移動・プログレスバー・alternate
screen を含む出力を eshell バッファ内に正しく描画する。マウス操作
(SGR mouse mode) や OSC 8 ハイパーリンクにも対応する。

eshell 統合専用であり、 ~M-x eat~ のような汎用のスタンドアロン端末
エミュレータは提供しない。「eshell の外部プロセス出力をすべて端末
エミュレーション経由にする」というアプローチは eat-eshell-mode と
同じだが、バックエンドが独自実装ではなく ghostty 本体の VT パーサ・
状態機械 (~ghostty-vt~) である点が異なる。PTY と子プロセスは Emacs
側が所有し、モジュールはバイト列を受け取って更新差分を返すだけの
純粋な状態機械になっている。

* 必要環境

- Emacs 31 以降 (それより前のバージョンへの互換コードはない)
- ビルドには Zig 0.17.0 系と、terminfo データベース生成用の ~tic~
  (ncurses)、本マニュアルの Info 生成用の ~makeinfo~ (texinfo) が必要
- nix (flake) でのビルド・利用を推奨。手動での ~zig build~ にも対応

* インストール

** nix flake から (推奨)

~nix build github:Warashi/emacs-spectreshell~ (リポジトリを checkout
済みなら単に ~nix build~) で ~result/~ 以下にダイナミックモジュール
(~lib/libspectreshell.so~)・Elisp ファイル
(~share/emacs/site-lisp/*.el~)・terminfo データベース
(~share/terminfo/~) が生成される。

#+begin_src elisp
;; ~/.config/emacs/init.el 等
(use-package spectreshell-eshell
  :load-path "/path/to/nix/build/result/share/emacs/site-lisp"
  :demand t
  :config (spectreshell-eshell-mode 1))
#+end_src

~spectreshell.el~ は ~require~ された時点で ~libspectreshell.so~ を、
~spectreshell-eshell.el~ は同梱の terminfo データベースを、いずれも
自分がロードされた場所からの相対パスで自動検出する。 ~load-path~ に
~result/share/emacs/site-lisp~ を通すだけでこのレイアウトのまま動き、
手動での ~module-load~ や ~TERMINFO~ の設定は不要。

** 手動で zig build

#+begin_src sh
git clone https://github.com/Warashi/emacs-spectreshell
cd emacs-spectreshell
zig build            # zig-out/lib/libspectreshell.so ほかを生成
#+end_src

~zig-out/lib/libspectreshell.so~ と ~zig-out/share/terminfo~ が
リポジトリルートの ~spectreshell.el~ から見て決め打ちの相対位置に
できるため、 ~load-path~ にリポジトリのルートディレクトリを追加する
だけで nix ビルドと同様に自動検出される。

* 設定

~spectreshell-eshell-mode~ はグローバルマイナーモード。一度有効に
すれば以後すべての eshell バッファの外部プロセス実行に適用される
(バッファごとに有効化する必要はない)。 ~(spectreshell-eshell-mode -1)~
で無効化すれば eshell は通常の (端末エミュレーションなしの) 動作に
戻る。

- ~spectreshell-term-name~ :: 子プロセスの ~TERM~ に設定する端末名。
  既定は ~xterm-ghostty~ で、同梱 terminfo が見つからない環境では
  自動的に ~xterm-256color~ にフォールバックする。
- ~spectreshell-terminfo-directory~ :: 同梱 terminfo データベースの
  ディレクトリ。既定の ~nil~ ならロード位置からの相対パスで自動検出
  する。

どちらも既定値のままで自動検出・自動フォールバックが効くため、通常は
明示設定は不要 (詳細は各変数の docstring を参照)。

~xterm-set-window-title~ を ~t~ にしていると、Emacs はコマンドのたびに
~frame-title-format~ を外側の端末のタイトルに送るので、子のタイトルは
次の打鍵で上書きされる。子のタイトルを残すには ~frame-title-format~ に
出す:

#+begin_src emacs-lisp
(defvar-local my-spectreshell-title nil)
(add-hook 'spectreshell-title-functions
          (lambda (_obj title) (setq my-spectreshell-title title)))
(setq frame-title-format '(:eval (or my-spectreshell-title "%b")))
#+end_src

子の 16 色 (SGR 30〜37 ・ 90〜97 と 40〜47 ・ 100〜107) は Emacs の
テーマに従い、 ~ansi-color-*~ の face の色で描く。子の色の問い合わせ
(OSC 4) にもその色で答える。tty フレームの Emacs が 24bit 色で描くとき
( ~(display-color-cells)~ が 16777216。 ~TERM=xterm-ghostty~ や
~COLORTERM=truecolor~ のとき) は、その色が RGB で外側の端末へ出るので、
外側の端末のテーマの色とは違う。外側のテーマに合わせたいときは、任意で
face をその色にする (face を変えても、描いた後の文字の色は変わらない。
問い合わせには、次にテーマを切り替えるかウィンドウが変わるまで前の色で
答える):

#+begin_src emacs-lisp
;; 色は外側の端末のテーマの値。16 色ぶん書く
(dolist (c '((ansi-color-red . "#cc6666")
             (ansi-color-green . "#b5bd68")))
  (set-face-attribute (car c) nil :foreground (cdr c) :background (cdr c)))
#+end_src

Emacs が 256 色で描くとき ( ~COLORTERM~ の無い ~TERM=xterm-256color~
など) は、既定の face のままなら bright black と bright blue 以外は
色番号で出るので、外側のテーマの色で見える。問い合わせには Emacs の
色で答えるので、見える色とは違うことがある。

** クリップボード

子 (Claude Code ・ Copilot CLI など) がクリップボードを読み書きする
OSC 52 と OSC 5522 (kitty のクリップボード) は、外側の端末へは中継せず
Emacs のクリップボードで受ける。扱うのは text だけで、 ~text/plain~ と
その別名 ( ~text/plain;charset=utf-8~ ・ ~UTF8_STRING~ ・ ~TEXT~ ・
~STRING~ ) を同じものとして扱う。

- ~spectreshell-clipboard-write~ :: 子の書き込みを許すか。 ~allow~
  (既定) は確認せずに書き、 ~ask~ はミニバッファで確認してから書き、
  ~deny~ は捨てる。確認で ~C-g~ を押すと拒否になる。batch・クライアント
  のいない daemon・端末のバッファが見えていない (「機能一覧」の可視性の
  問い合わせと同じ意味) ときは、 ~ask~ でも確認せずに捨てる
- ~spectreshell-clipboard-read~ :: 子の読み取りに答えるか。 ~ask~ (既定)
  は確認してから答え、 ~allow~ は確認せずに答え、 ~deny~ は空で答える。
  確認できないときと ~C-g~ は、 ~ask~ でも拒否になる。OSC 5522 で
  種類の一覧だけ、または text 以外の MIME (画像など) だけを求める
  読み取りには、中身を明かさないので ~ask~ でも確認せずに答える (一覧
  には ~text/plain~ と答え、text 以外の中身は返さない)

確認には、そのたびに作る 4 文字の語 (紛らわしい 0 ・ o ・ 1 ・ l ・ i
を除いた英小文字と数字) を出す。

#+begin_example
Spectreshell: "vim" in "eshell" wants to read the clipboard.  Allow once: kq7m / Always allow: x3pd / Anything else denies:
#+end_example

表示された語を打って ~RET~ で決めたときだけ許し、それ以外 ( ~RET~ だけ
や ~yes~ を含む) はすべて断る。子が自分の問いを表示して、利用者がそれに
答えて打った語を確認の答えに取らせないため。補完と履歴は使わない。

確認は、打っている途中のキーを答えに取らないよう、キー入力が 0.5 秒
止まってから出す。答えた後の次の確認も、答えてから 0.5 秒入力が無ければ
出る。ミニバッファを使っている間、キーボードマクロの記録中と実行中、
コマンドの実行中、打ったキーがまだ読まれていない間も出さず、それが
終わってから出す (記録中のマクロや、先に打ったキーに答えが入らないよう
にするため)。確認は、選択中のフレームが端末のバッファを表示するまで待つ
(daemon に複数のクライアントがいても、バッファを見ていない端末に確認を
出さない)。出せない間は確かめる間隔を最長 2 秒まで伸ばし、キーを押すと
0.1 秒に戻す。確認の直前に端末のバッファがもう見えていなければ、確認
せずに断る。

OSC 5522 で子が名前とパスワードを添えたときは、確認に名前を出し、
常に許可の語 (以後も許す) も出す。名前とバッファ名 (子のタイトルから
付くことがある) は、文字と 10 進の数字 (ほかの文字体系を含む)・ASCII の
空白・ ~-_.:/+@~ だけを残し、40 桁までに切って ~"~ で括る。文字でも、
ハングルの埋め字のような見えないものと、 ~ʼ~ (U+02BC) のような除いた記号
に似たものは除く ( ~*eshell*~ は ~"eshell"~ と出る)。常に許可の語を
打つと、同じパスワードの以後の要求は確認しない。覚えたパスワードは子の
RIS ( ~\ec~ ) で消える。確認を待つ間に子が RIS を出したら、RIS の前の
要求 (OSC 52 と OSC 5522 の読み書きのすべて) は確認せずに捨てる。確認の
間に RIS が来たら、許可と答えても書き込まず、読み取りにも答えず、常に許可
でも覚えない。確認の要らない要求 ( ~allow~ など) は RIS の後でも処理する。

OSC 5522 の書き込みは、子が出力した時点で成否を答える。 ~deny~ なら
EPERM と答えるが、 ~ask~ でも先に成功 (DONE) と答えるので、後の確認で
断った書き込みは、子には成功と見えたまま捨てられる。text の無い書き込み
(画像だけなど) には ENOSYS と答える。

子が kitty の paste イベント (mode 5522) を求めている間の ~C-y~
( ~spectreshell-yank~ ) は、本文の代わりに paste イベント (種類の一覧
~text/plain~ と一度きりのパスワード) を送り、子はそれを使って kill-ring
を読む。この読み取りには ~ask~ でも確認せずに答える。
~spectreshell-clipboard-read~ が ~deny~ のときは、読み取りが断られて
貼り付けが消えるので、イベントにせず本文をそのまま送る。端末側の
貼り付け ( ~xterm-paste~ ) と ~eshell-send-input~ で送るものは、mode
5522 でも本文のまま送る。DECRQM ~?5522~ には今の値 (1 / 2) で答える

読み書きは、子が出力した直後ではなく、出力を描いた後に端末ごとに来た順に
処理する。確認はすべての端末を通して一度に 1 つだけ、端末ごとに順番に
出し、確認を待つ端末の後の要求はその確認を待つが、ほかの端末の確認の
要らない要求は待たずに処理する。1 つの端末で処理を待つ要求は 64 件までで、超えた分は待たせずに断る。
確認で ~C-g~ を押すと、その要求に加えて、同じ端末で確認を待っている要求も
すべて断る (確認を出し続ける子を止めるため)。読み取りには、 ~current-kill~ で見た kill-ring
の先頭 (ほかのアプリケーションが新しく選択したものがあればそれ) で、
Ghostty と同じく要求の種別によらず clipboard を読んで答える。答えるまでに
ジョブが終わったら答えない。

clipboard への書き込みは ~kill-new~ で kill-ring に入るので、 ~C-y~ で
貼れる。外側への反映は ~interprogram-cut-function~ に任せるので、GUI
フレームではシステムのクリップボードに入り、tty フレームでは xterm.el が
OSC 52 で外側の端末へ送る。xterm.el が送る先は、端末のバッファを表示して
いるフレームではなく、そのとき選択中のフレームの端末で、Emacs が外側の
端末の DA1 で OSC 52 を書けると判断した端末 (端末パラメータ
~xterm--set-selection~ が ~t~ ) に限る。外側の端末が書き込みを許して
いなければ (Ghostty の ~clipboard-write = deny~ ) 外側には入らない。

xterm.el は base64 にして ~xterm-max-cut-length~ を超える書き込みを
送らず、警告して 2 秒待つ。その場合は外側へは送らず kill-ring にだけ入れ、
エコー領域で知らせる。primary (OSC 52 の ~p~ ・ ~s~ ) への書き込みは
~gui-set-selection~ で ~PRIMARY~ に入れ、kill-ring には入れない。長すぎる
primary への書き込みは捨てて知らせる。

* 使い方

外部プロセスの実行中、eshell バッファは端末として振る舞う。プロセスが
終了すると出力は通常のバッファテキストとして確定化され、いつもの
eshell 編集に戻る。

確定化では行末のパディング (端末が桁数ぶんまで詰めた空白) を落とし、
端末のカーソルが通り過ぎた行までを残す。 =printf "\n\n\n"= のように
コマンドが最後に出した空行はそのまま残り、そのコマンドが一度も
描かなかった行だけが畳まれて、次のプロンプトが出力の直下に来る。

** semi-char モードと emacs モード

前景ジョブの実行中は 2 つの入力モードを切り替えて使う。

- semi-char モード (実行中のデフォルト) :: 印字可能キー・矢印・C-a 等
  ほとんどのキーをそのまま実行中プロセスへ送信する。Emacs 側に残るのは
  後述の一覧のキーだけで、 ~C-x o~ や ~C-x b~ でそのまま別ウィンドウ・
  別バッファへ移動できる。 ~C-y~ は kill-ring の内容を bracketed
  paste としてプロセスへ送る (日本語もこの経路で送信できる)。point は
  常に端末のカーソル位置に追従する。
- emacs モード :: 全キーが通常の Emacs 操作になる。実行中の出力を
  さかのぼって閲覧・コピーする用途。point をカーソル位置から動かして
  いる間は、新しい出力があっても point は動かない。出力がスクロール
  しても point と画面は同じ内容の行を指したままなので、読んでいる
  場所がずれない。カーソル位置へ戻せば再び出力に追従する。追従はウィンドウごとに判定するので、
  一方のウィンドウで履歴を読みながら、もう一方で出力を追い続けられる。
  ジョブ終了時 (出力の確定化) も、端末領域の外にある point はそのまま
  据え置かれる。読んでいた位置から新しいプロンプトへ飛ばされない。
  ただし RET だけは例外で、端末領域より後ろに書いた文字をそのまま
  実行中プロセスへ送って消す (semi-char モードでの入力と同じ扱い)。
  書いた行は、プロセス側でエコーが有効なら端末領域に現れる

キーバインド:

- ~C-c C-e~ :: semi-char モードから emacs モードへ切り替える
- ~C-c C-j~ :: emacs モードから semi-char モードへ復帰する
- ~C-\~ :: 次の 1 キーを Emacs に渡さず、そのままプロセスへ送る。
  ~C-\ C-x~ ・ ~C-\ M-x~ ・ ~C-\ C-u~ ・ ~C-\ C-y~ のように、下記の
  Emacs に残したキーを送るのに使う。 ~C-\ C-\~ で ~C-\~ 自体を送る。
  ~C-x C-e~ のようなキー列は 1 キーずつ ~C-\ C-x C-\ C-e~ と打つ
- ~C-c C-c~ :: ~C-c~ をプロセスへ送る (eshell の
  ~eshell-interrupt-process~ ではない)。Claude Code のように ~C-c~ を
  自分で解釈するプログラムにはキーとして届き、そうでないプログラムは
  端末と同じく SIGINT で止まる。eshell の ~C-c C-k~ (kill) ・
  ~C-c C-\~ (quit) ・ ~C-c C-d~ (EOF) はそのまま使え、emacs モードでは
  ~C-c C-c~ も eshell の ~eshell-interrupt-process~ に戻る
- ~ESC ESC~ :: ESC 1 個をプロセスへ送る (vim / less / fzf を抜ける)

端末フレームの Emacs では ESC は次のキーを待つプレフィックス
(~meta-prefix-char~) なので、ESC を 1 打鍵で送ることはできない。
~ESC ESC~ がその脱出口で、ESC を 1 バイトだけ送る。

semi-char モードで直接はプロセスへ送られず、通常の Emacs のキーとして
働くのは次のキーだけである。 ~C-c~ ・ ~C-x~ ・ ~M-x~ ・ ~C-u~ ・ ~C-y~ は
~C-\~ に続けて打てば送れる。

- ~C-c~ ・ ~C-x~ プレフィックス :: ~C-x o~ ・ ~C-x b~ 等の
  ウィンドウ・バッファ操作を端末バッファからそのまま使えるように残して
  ある ( ~C-c C-e~ ・ ~C-c C-c~ だけは semi-char モードの束縛)
- ~M-x~ :: コマンド実行のために残してある
- ~C-u~ :: ~universal-argument~ として Emacs に残してある
- ~C-y~ :: kill-ring の内容を paste として送る (上記)
- ~C-g~ :: Emacs の ~quit-char~ 。Emacs がキー入力を待っている間は
  通常のキーとして読まれるので、semi-char モードでは子プロセスへ
  送られる (vim ・ less の ~C-g~ が使える)。ただし Emacs が Lisp を
  実行中に押した ~C-g~ は quit として働き、送られない。 ~quit-char~
  を変えて常に送る手は、利用者の脱出口が無くなるので採らない
- ~M-O~ ・ ~M-[~ :: 端末は矢印・F1〜F4・Home/End を ~ESC O …~ (SS3) や
  ~ESC [ …~ (CSI) として送ってくる。Emacs の ~input-decode-map~ が
  それを変換できるのは、そこまでのキー列がどのキーマップでも未束縛の
  ときだけなので、この 2 つを空けてある。kkp ( kitty keyboard を外側の
  端末と使うパッケージ) の変換も ~ESC [~ で始まるので、kkp を使っても
  束縛できない。kkp を使っていれば ~M-O~ ・ ~M-[~ は 1 キーで届くので、
  ~C-\ M-O~ ・ ~C-\ M-[~ で送れる
- ~ESC ESC ESC~ ( ~keyboard-escape-quit~ ) :: ~ESC ESC~ が上記の
  「ESC を送る」束縛なので、3 打鍵目まで届かず影に入る

小文字の ~M-o~ を含む他の ~M-<英字>~ ・ ~M-<数字>~ ・ ~M-<記号>~ ・
~C-M-<英字>~ 、 ~C-@~ ~C-]~ ~C-^~ ~C-_~ 、 ~M-DEL~ 、
Insert / Delete 、 TAB / S-TAB 、矢印と F1〜F12 、端末側の paste 、
マウスはすべてプロセスへ送られる。GUI フレームや kkp のもとで別の
キーとして届く ~C-S-<英字>~ や ~C--~ ・ ~C-1~ ・ ~C-SPC~ ・ ~C-/~ などの
~C-<記号・数字>~ も送られる。

** 背景ジョブ (~cmd &~)

~&~ を付けて起動した背景ジョブは、自分の端末領域と描画だけを持つ。
semi-char モードには入らないのでキーボードは奪われず、実行中も
コマンドラインはそのまま編集でき、次のコマンドも普通に実行できる。
背景ジョブの出力はプロンプトの上にある自分の領域へ追記されていく
ので、前景の出力と混ざらない。

背景ジョブへの対話入力はできない (実端末でも背景ジョブは端末からの
読み込みで止まる)。入力が必要なコマンドは前景で実行する。

** マウス

クリック・ドラッグ・ホイールスクロールは端末座標に変換して実行中
プロセスへ送信される (SGR mouse mode)。マウストラッキングを使わない
コマンドの実行中は、通常の Emacs マウス操作 (~mouse-set-point~ /
ホイールスクロール) にフォールバックする。

OSC 8 のリンクは、マウストラッキングを使わないコマンドの実行中なら
クリックで ~browse-url~ を呼ぶ。マウストラッキング中のクリックは
リンクの上でもプロセスへ送り、リンクは開かない。 ~browse-url~ は Emacs
が動いているホストで走るので、ssh 先の daemon に ~emacsclient -t~ で
つないでいるときは、手元ではなく ssh 先でリンクを開こうとする。

tty フレーム (~emacs -nw~) では、その前提として Emacs 側の
~xterm-mouse-mode~ が有効になっている必要がある。これが無効だと
クリックがそもそも Emacs のキーイベントにならず、spectreshell は何も
受け取れない。Emacs は端末の種類によっては起動時に自動で有効にするが、
そうでない環境では利用者が自分で有効にする。

#+begin_src emacs-lisp
(xterm-mouse-mode 1)
#+end_src

グローバルなモードを勝手に切り替えないため、spectreshell 側で自動的に
有効にはしない。GUI フレームでは不要。

** スクロールバック

可視領域から流れ出た行は Emacs バッファへ確定化されるので、isearch・
コピー・ ~eshell-previous-prompt~ などの Emacs の機能がそのまま効く。
less や vim などの alternate screen アプリの画面は確定化されず、
終了時に消えて元のプロンプト位置に戻る。

* 機能一覧

- SGR 全般 (16色 / 256色 / 24bit)、カーソル制御、スクロール領域、
  alternate screen (less・vim 等)、bracketed paste
- タイトル変更 (OSC 0/2) の通知: ~spectreshell-title~ で最新値を参照
  でき、変更時には ~spectreshell-title-functions~ が呼ばれる。
  ~spectreshell-eshell-mode~ はこの hook に ~spectreshell-relay-title~
  を足し、子のタイトルを外側の端末へ OSC 2 で送る (制御文字は除く)。
  外側へ送らないなら hook から外す。バッファ名やフレームタイトルへの
  反映はユーザー側のフック実装に委ねる
- マウス (SGR mouse mode)
- XTVERSION ( ~\e[>q~ ) には Ghostty と同じく、同梱する ghostty の版で
  ~ghostty 1.4.0~ のように答える。マウスはセル座標でしか送れないので、
  DECRQM ~?1016~ (SGR pixel 座標) には未対応 (0) と答える
- カーソル位置の問い合わせ ( ~\e[6n~ ) には ~\e[行;桁R~ で、DECXCPR
  ( ~\e[?6n~ ) には Ghostty と同じくページ番号 1 を添えた
  ~\e[?行;桁;1R~ で答える。DECOM ではスクロール領域からの相対位置
- Backspace は DEL (0x7f) を送る。子が DECBKM ( ~\e[?67h~ ) を立てると
  Ghostty と同じく BS (0x08) を送る
- 書記素クラスタ (mode 2027) は Ghostty と同じく既定で有効で、RIS
  ( ~\ec~ ) 後も有効に戻る。国旗・ZWJ でつないだ絵文字・肌色修飾は
  1 つの書記素として 2 セルを占める。子は ~\e[?2027l~ で無効にできる
- 子が外側の端末へ向けて出すものは、バッファを表示している tty
  フレームの端末へ送る。同じ端末のフレームが複数あっても 1 回だけ送り、
  GUI フレームには送らない。どの tty フレームも表示していない間
  (daemon にクライアントがつながっていないときなど) に出たものは捨て、
  後から送り直さない
- 子の OSC 52 によるクリップボードへの書き込みと読み取りは、Emacs の
  クリップボードで受ける (「設定」のクリップボードを参照)
- デスクトップ通知 (OSC 777 / OSC 9) は OSC 777 にして送る。タイトルと
  本文から制御文字を除き、タイトルからは ~;~ も除く。通知を出すかは
  外側の端末の設定 (Ghostty の ~desktop-notifications~ ) に従う
- 進捗 (OSC 9;4) は送ったうえで最新の状態をバッファごとに覚え、
  バッファを新たに表示したウィンドウの端末へ送り直す。進捗を残した
  ままジョブが終わったときと、バッファを kill したときは消去
  (~\e]9;4;0\a~) を送る
- 子がフォーカスの報告 (mode 1004) を有効にしている間は、フォーカスの
  変化を ~\e[I~ / ~\e[O~ で子へ送る。端末のバッファを選択中のウィンドウ
  に表示しているフレームにフォーカスがあれば、フォーカスがあるとみなす。
  tty フレームのフォーカスは外側の端末の報告に従い、報告が無ければ
  フォーカスがあるとみなす
- 子の明暗の問い合わせ ( ~\e[?996n~ ) には、バッファを表示している
  フレームの ~background-mode~ で Ghostty と同じく答える。子が mode 2031
  を有効にしている間は、テーマの切り替えなどで明暗が変わると子へ知らせる
- 子の可視性の問い合わせ ( ~\e[?998n~ ) には、Ghostty と同じく
  ~\e[?999;1n~ (見えている) か ~\e[?999;2n~ (見えていない) で答える。
  子が mode 2033 を有効にした時点と、その間に可視性が変わったときも
  同じ報告を送る。見えているとは、daemon の初期フレームを除く、見えて
  いるフレームのどれかのウィンドウ (選択中でなくてよい) がバッファを
  表示していること。tty のフレームは、同じ端末で一番上にあるとき
  (子フレームはそのルートが一番上にあるとき) だけ見えているとする。外側の
  端末の別のタブに隠れていても Emacs には分からないので、見えていると
  みなす。フレームの可視性の変化には
  hook が無いので、アイコン化・復帰に伴うフォーカスの変化で引き直す。
  フォーカスを変えずに隠したり出したりする WM では、次の契機まで報告が遅れる
- 子の色の問い合わせ (OSC 10 / 11 / 4) には、spectreshell が描く色で
  Ghostty と同じ形 ( ~\e]11;rgb:RRRR/GGGG/BBBB~ 、終端は問い合わせと
  同じ) で答える。
  OSC 10 / 11 にはバッファを表示しているフレームの ~default~ face の
  前景・背景、OSC 4 の 0〜15 には ~spectreshell-color-N~ の前景 (背景色
  の SGR 40〜47 ・ 100〜107 は同じ face の背景で描く)、16〜255 には xterm の 256 色の値で答える。tty フレームでは Emacs が
  出す色 (256 色なら寄せた色) になり、 ~default~ の色が決まっていない
  ( ~unspecified-fg~ / ~-bg~ ) ときは OSC 10 / 11 に答えない。色は
  テーマの切り替えと、ウィンドウのバッファ・選択の変化のときに引き直す。
  子による色の設定・リセットは効かず、OSC 12 などほかの色には答えない
- 子の BEL は外側の端末へ BEL で送る (~ding~ は使わない)。どう示すかは
  外側の端末の設定 (Ghostty の ~bell-features~ ) に従う
- OSC 8 ハイパーリンク (クリック可能な button として描画)
- ~xterm-ghostty~ の terminfo をビルド時生成・同梱し、 ~TERM~ /
  ~TERMINFO~ として子プロセスに自動注入
- ~emacsclient~ のフレームでコマンドを始めると、その ~emacsclient~ の
  環境にある ~TERM_PROGRAM~ / ~TERM_PROGRAM_VERSION~ を子プロセスに
  渡す。無い変数は、daemon や eshell で設定した値があっても子から外す。
  ~emacsclient~ のフレームでなければ Emacs 自身の値がそのまま渡る
- 端末サイズはウィンドウの表示桁数・行数を pty に設定して伝える。
  この段の子プロセスからは環境変数 ~COLUMNS~ / ~LINES~ を外すので、
  幅・高さの情報源は pty ( ~TIOCGWINSZ~ ) だけになり、リサイズにも
  常に追従する。パイプの最終段以外は pty を持たないため、そちらでは
  eshell 本来の ~COLUMNS~ / ~LINES~ がそのまま渡る。同じバッファを
  複数のウィンドウに出しているときは、サイズが変わった時点で選択
  されているウィンドウのサイズに合わせる。どれも選択していなければ
  表示しているウィンドウのうち 1 つになる。選択を別のウィンドウへ
  移しただけでは端末サイズは変わらない (サイズ変更の通知が無いため)。
  フレームを消したとき (別の ~emacsclient~ を閉じたときなど) も合わせ
  直す。pty のサイズは常に端末と同じにし、Emacs 標準の
  ~window-adjust-process-window-size-function~ には従わない

* 既知の制限

- char モード非対応: 全キー送信は v1 のスコープ外。semi-char モードで
  Emacs 側に残るキー ( ~C-c~ ・ ~C-x~ ・ ~M-x~ ・ ~C-u~ ・ ~C-y~ ) は
  ~C-\~ に続けて 1 キーずつ送る。 ~M-O~ ・ ~M-[~ は直接は送れず、kkp を
  使っているときに ~C-\~ 経由で送る
- 実行中プロセスへの Emacs 側 input method は対象外: ddskk 等は
  eshell のコマンドライン編集中 (プロセス非実行時) は無条件で動くが、
  プロセス実行中の semi-char モードでは動かない (キーはバッファに
  挿入されず直接送信され、 ~C-\~ は次のキーを送るキーになる)。
  一方、文字が Emacs のキーイベントとして届きさえすれば
  (端末エミュレータ側の IME など)、その文字は UTF-8 のバイト列として
  そのまま子プロセスへ送られる。 ~C-y~ (kill-ring からの
  bracketed paste) 経由での日本語送信も可能
- GUI フレームでは、選ばれたグリフが端末のセル幅を超える書記素
  (絵文字フォントで描かれる ⏱ ・国旗 ・ ZWJ でつないだ絵文字など) を
  縮めて表示し、行の折り返しを防ぐ。縮めても、元から狭いグリフ (CJK
  など) でも、足りない幅は余白で端末のセル幅にそろえ、後続の文字の
  位置がずれないようにする
- tty フレームでは、ZWJ でつないだ絵文字・肌色修飾など、Emacs が端末の
  セル数より広く数える書記素を静的に合成 (~compose-string~ ) して幅を
  そろえる。単独の regional indicator と VS16 の付いた絵文字 (❤️ など)
  は Emacs が 1 桁と数えるので外側の端末 (2 セル) より狭いまま残り、
  その後ろの文字で Emacs の桁と外側の表示がずれることがある
- GUI の幅揃えと tty の合成のどちらを使うかと GUI の幅は、行を描いた
  ときに選択中のフレームで決まる。GUI と tty のフレームに同じバッファを
  出しているときは、選択していなかったほうでずれる
- ボタンを押さないマウスの移動 (mode 1003 のホバー) は子へ送らない。
  ドラッグ中の移動・クリック・ホイールは送る
- tty フレームでは、子がカーソルを隠しても ( ~\e[?25l~ ) Emacs の
  カーソルは point (semi-char モードでは端末のカーソル位置) に出たまま
  になる。カーソルを自分で描くプログラム (Claude Code ・ Copilot CLI
  など) では、カーソルが 2 つ見えることがある
- 子の 16 色は Emacs のテーマ ( ~ansi-color-*~ ) に従い、外側の端末の
  テーマには従わない。Emacs が 24bit 色で描く tty フレームでは、外側で
  直接動かしたときと色が違う (合わせる face の設定は「設定」を参照)
- バッファローカルの face の remap ( ~face-remap-add-relative~ 、
  solaire-mode など) は、色の問い合わせへの答えと、隠し文字 (SGR 8)
  の色に反映されない
- 色の問い合わせへの答えはバッファを表示しているフレームで、描画は
  feed のときに選択中のフレームで face を解決する。tty と GUI の
  フレームが混在し、テーマが表示の種類で face を分けていると、答えと
  描く色が食い違うことがある
- 子から見える端末はウィンドウの本文の大きさなので、外側の端末より
  小さい。行はメニューバー・モードライン・エコー領域などのぶん減る
  ( ~menu-bar-mode~ を切る、端末のバッファで ~mode-line-format~ を
  ~nil~ にすると増える)。桁は折り返しの印のために最後の 1 桁を使わない
  ( ~truncate-lines~ でも変わらない)
- 画像 (kitty graphics/sixel) は未実装
- TRAMP / リモート ~default-directory~ は対象外: リモートでは常に
  eshell 本来の (非端末) 経路にフォールバックする
- パイプラインは末尾のプロセスのみ端末に接続: ~cmd1 | cmd2~ の
  ~cmd1~ の出力は spectreshell を経由しない
- Emacs が新規に開く pty は既定で ~-echo -onlcr~ になっており、素の
  LF だけの出力が階段状にずれてしまうため ~stty ... sane~ 経由で回避
  している。 ~/bin/sh~ と ~stty~ が存在しない環境 (通常の Unix 系では
  まず問題にならない) では機能しない
