既知の未対応課題を管理するファイル。対応したら =DONE= に移し、対応
コミットを本文に記録するか、末尾の対応済み一覧へ 1 行で移す。

外部条件や実測結果を待って保留している項目は =WAIT= に置く。条件を
再検証したら日付と結果を本文に追記し、条件が満たされて対応できたら
=DONE= に移す。

各項目の ID (M-3, L-2, P-1 など) は初出のリポジトリ全体レビュー
(2026-07-18 実施) での採番で、過去のコミットメッセージからも参照されて
いるため維持する。詳細な指摘本文と検証記録は当時のファイル
(=docs/code-review-issues.org=) の git 履歴を参照。

レビュー後に見つかった課題は同じ体系の続き番号 (L-21 以降など) を振る。

* 機能・堅牢性

** DONE M-3: 同一バッファでの並行ジョブで端末領域が交錯する
対象: =spectreshell.el= (端末領域) / =spectreshell-eshell.el=
(=--attach= / gather advice)

=spectreshell--current= / =spectreshell-eshell--process= が単一スロット
のため、=command &= 実行中に次のコマンドを打つと後発 attach が先発を
上書きし、双方が「marker〜point-max」を自領域とみなして削除・上書きし
合う。先発の detach は後発ジョブ実行中でも無条件に semi-char モードを
解除する。実際には =cmd &= 実行中に打った文字がコマンドラインに入らず
背景ジョブの pty へ送られ、コマンドが実行できなかった。

対応は 3 コミット:

1. 3cd8e4d: 端末領域の終端をプロセスごとのマーカーにする。point-max を
   見ていた箇所 (行数計算・パディング・余剰行削除・alt screen の
   保存/復元・確定化・カーソル位置算出) をすべて終端マーカー経由に
   変え、領域外のテキストを壊さないようにする。insertion type は t
   ではなく nil を選んだ (=t= だと空の領域の直後に eshell が出す
   プロンプトを飲み込む)。併せて semi-char の無条件カーソル追従を
   =spectreshell--current= の端末に限り、カーソル位置とマウス座標を
   領域内にクランプし、finalize が領域外の point を動かさないように
   する。
2. 2fd2ca7: =spectreshell-start= に COMPACT を足し、末尾の空行を畳む
   領域を選べるようにする。モジュールは最初の更新で全行を dirty に
   するため、これが無いと 1 行しか出力しない背景ジョブでも領域が
   rows 行に広がり、プロンプトが 1 画面ぶん下へ落ちる。
3. cc662ec: attach 済みの (プロセス . 端末) 一覧を持ち、キー入力の
   宛先と semi-char モードを前景ジョブ (gather advice の中で読んだ
   =eshell-current-subjob-p= が nil) だけのものにする。背景ジョブは
   領域と描画だけを持ち、その detach では semi-char も
   =eshell-last-output-end= も触らない。リサイズは全プロセスに適用。

追補 (46a78f9): 何も出力しなかったジョブの領域が確定時に空行を
残し、プロンプトと打ちかけの入力を 1 行押し下げていたのを直した。

パイプラインの最終段だけ端末に接続する割り切りは維持した (接続先が
ジョブごとに独立した領域になったので、並行ジョブとは両立する)。

ERT: =test/spectreshell-test.el= の領域終端・COMPACT 関連テスト群と、
=test/spectreshell-eshell-test.el= の
=spectreshell-eshell-test-background-job-leaves-command-line-usable=
(=:expected-result :failed= を外した) ・
=--foreground-command-runs-during-background-job= ・
=--background-and-foreground-regions-do-not-interleave= ・
=--background-job-exit-keeps-foreground-semi-char= ・
=--window-size-change-resizes-every-attached-terminal= 。

実端末での再確認 (2026-09-05, tmux 80x24, =emacs -nw -Q -L . -l
spectreshell-eshell=):

1. =sh -c 'i=0; while [ $i -lt 15 ]; do echo "BG-$i"; sleep 0.4; i=$((i+1)); done' &=
2. 背景ジョブの出力が続いている間に =printf 'FG-A\nFG-B\n'= を打って RET

打った文字はコマンドラインに入り、コマンドが実行されて =FG-A= /
=FG-B= が出力された。背景ジョブの出力 (=BG-0= 〜 =BG-14=) は自分の
領域に 1 行も欠けずに並び、前景の出力とも混ざらない。プロンプトは
背景ジョブの出力の直下に付き、空行の下へ落ちることもない。

** DONE L-2: キーマップの穴 (backtab / 修飾付き TAB・RET・DEL)
対象: =spectreshell.el= (semi-char keymap, =spectreshell--event-to-key=)

=backtab= (GUI の S-TAB)、=C-<tab>= / =M-RET= / =C-<backspace>= 等が
未束縛で Emacs 側コマンドに流れていた。=spectreshell--event-to-key= も
ascii 特殊キー判定が raw イベント完全一致だったため、=M-RET= が
=return= + alt にならなかった。

判定を「Emacs の修飾ビットだけを落とした文字」で行うようにし
(=spectreshell--event-char=)、=backtab= は =tab= + shift への読み替え表
(=spectreshell--aliased-key-symbols=) で扱う。束縛側は修飾付き特殊キーの
ループに tab / return / backspace / escape / backtab を追加した
(900d340・234e9b9・cd38ac4、=test/spectreshell-key-table-test.el= の
=M-RET= / =C-<backspace>= / =<backtab>= 行)。

** DONE L-19: シフト付き英字が小文字で送られる
対象: =spectreshell.el= (=spectreshell--event-to-key=)

=event-basic-type= が =?A= を =?a= に落として shift を修飾子側へ移す
ため、KEY が =("a" shift)= になり PTY には =a= が出ていた。EVENT が
BASIC の upcase 形そのものなら生の EVENT を KEY に使うようにして対応
(7a3a954、=test/spectreshell-key-table-test.el= の =A= / =Z= 行)。

meta 併用の大文字 (=M-A=) は meta ビットにより =characterp= の外へ出る
ため当初は対象外だったが、修飾ビットを落とした文字で判定するよう改めて
対応した (900d340・3a9fe0d、=M-<大文字>= の束縛追加を含む。同じ表の
=M-A= 行)。

** DONE L-20: C-M-<letter> がキーマップに無く送られない
対象: =spectreshell.el= (semi-char keymap)

キーマップは =C-<letter>= と =M-<letter>= を個別に束縛しているだけで
=C-M-<letter>= の組が無く、Emacs 側のコマンドに流れていた。
=--event-to-key= は =?\C-\M-a= を =("a" ctrl alt)= に正規化できていた
ので、a-z 全字の束縛を足して対応 (a031601、
=test/spectreshell-key-table-test.el= の =C-M-a= 行)。docs/design.org の例外は =C-c= / =C-x= プレフィックス・
=M-x=・=C-y= で、どれも =C-M-= 版とは別イベントのため除外は設けていない。

** DONE L-21: パイプ最終段で pty の termios が正されない
対象: =spectreshell-eshell.el= (=--wrap-command-for-pty=)

pty を Emacs が開いた直後の既定は =-onlcr= で、そのままだと LF が改行
にならず出力が階段状になる。これを避ける =stty= ラッパは当初 =term.el=
の =term-exec-1= と同じく標準入力に対して =stty= していたが、
spectreshell が pty 化するのは出力側だけ (=--force-pty-output=)
であり、パイプの最終段では標準入力が eshell の plain pipe になる。=stty= が ENOTTY で失敗し (stderr は =null-device=
送りで無言)、=ls | cat= のような日常的なパイプの出力がすべて階段状に
崩れていた。

=stty= の対象を子プロセスの制御端末 =/dev/tty= (= Emacs が開いた pty)
に変えて対応 (0f650de、=test/spectreshell-eshell-test.el= の
=spectreshell-eshell-test-piped-output-lines-start-at-column-zero=)。

** DONE L-22: 子プロセスから見える端末幅が COLUMNS と ioctl で 1 桁ずれる
対象: =spectreshell-eshell.el= (=--process-environment= /
=--variable-aliases-list=)

=spectreshell-eshell--terminal-size= は桁数に
=window-max-chars-per-line= を使う。この値は tty フレームでは折り返しの
継続グリフのぶん最終桁が予約されるため =window-body-width= より
1 小さい。一方 eshell 本体 (=esh-var.el=) は子プロセスへ export する
=COLUMNS= を =window-body-width= で定義していたので、子から見た幅が
環境変数では 80、=TIOCGWINSZ= では 79 になっていた。80x24 の実端末での
修正前の実測値 (=tput cols= は COLUMNS を優先するため 80 を返す):

#+begin_example
$ sh -c "echo COLUMNS=$COLUMNS; stty size < /dev/tty"
COLUMNS=80
21 79
#+end_example

端末幅の定義は変えず、pty を付ける段の子から環境変数 =COLUMNS= /
=LINES= を外して =TIOCGWINSZ= を唯一の情報源にすることで対応
(7b52772、=test/spectreshell-eshell-test.el= の
=spectreshell-eshell-test-attached-child-has-no-columns-lines= と
=spectreshell-eshell-test-unattached-child-keeps-eshell-columns=)。
判断の根拠は docs/design.org の「端末サイズの伝え方」に記録した。
=window-body-width= 側へ寄せる案は継続グリフの桁と端末の最終桁が
衝突するため採らず、環境変数に正しい値を入れ直す案も exec 後には
更新できない以上リサイズのたびにまた食い違うため採らなかった。

一次情報として確認した点:

- =esh-var.el= の =eshell-variable-aliases-list= では =COLUMNS= /
  =LINES= の COPY-TO-ENVIRONMENT が =t= 。
  =eshell-environment-variables= がこのフラグを見て =setenv= するので、
  =esh-proc.el= 側の =process-environment= の let より後勝ちになる。
  よって alias のフラグを落とさないと抑止できない (実験でも確認)。
- ncurses 6.6 の =ncurses/tinfo/lib_setup.c= の
  =_nc_get_screensize= は =TIOCGWINSZ= を読んだ後に
  =_nc_getenv_num("LINES"/"COLUMNS")= で上書きする (=use_env= が真の
  ときで、=lib_data.c= の既定値は =TRUE=)。SIGWINCH 経路の
  =_nc_update_screensize= も =TINFO_GET_SIZE= 経由で同じ関数を呼ぶ
  ため、環境変数を残すとリサイズ後もずれが残る。

80x24 の tmux 上の =emacs -nw= での修正後の実測値:

#+begin_example
$ sh -c 'echo COLUMNS=${COLUMNS-unset} LINES=${LINES-unset}; stty size < /dev/tty; tput cols'
COLUMNS=unset LINES=unset
21 79
79
#+end_example

=tput cols= が =TIOCGWINSZ= と一致するようになった。GUI フレームでは
継続グリフの扱いが tty と異なる可能性があるが、この環境では GUI を
起動できないため未確認。ただし本修正は幅の値ではなく情報源を一本化
するものなので、GUI でもずれは生じない見込み。

COLUMNS を読まないコマンドの出力が 80 桁で折り返すのは、tty の Emacs
ウィンドウが元々 79 桁ぶんしか文字を表示できない (80 桁目が継続グリフ
用) ことによるもので、この課題とは別。

** DONE L-13: build.zig の terminfo install が system command 直書き
対象: =build.zig=

=mkdir -p= + =cp -R= の system command 直書きのため、ステップキャッ
シュが効かず毎回コピーが走り、Windows でも動かなかった。tic の
stderr も =captureStdErr= で捨てており失敗時の診断が出なかった。

=captureStdErr= を外して診断を出すようにし (aca7c44)、コピーを
=std.fs= で走査する自前の install ステップに置き換えた (bd3b6fb)。
更新が無ければ =result_cached= を立てるので二度目以降の =zig build=
では飛ばされる。

=std.Build.Step.InstallDir= を使わないのは、tic が別名 =ghostty= を
=x/xterm-ghostty= へのシンボリックリンクとして出力するのに対し、zig
0.15.2 の InstallDir の =make= がディレクトリと通常ファイル以外のエ
ントリを読み飛ばすため。

「install マニフェスト管理外」の指摘は zig 0.15.2 では対象外だった。
マニフェスト API (=pushInstalledFile= 等) は存在せず、
=std.Build.makeUninstall= が ziglang/zig#14943 の TODO panic なので、
=zig build uninstall= はどの build.zig でも動かない。

あわせて、tic が解析エラーでも終了コード 0 を返して空の出力を残す件
に対し、install 対象が 0 件ならステップを失敗させるようにした。

** WAIT B-1: zig 自前 x86_64 バックエンドの .so segfault が直ったら use_llvm を外す
対象: =build.zig= (=addLibrary= の =.use_llvm = true=)

zig 0.15.2 の自前 x86_64 バックエンド (Debug ビルドの既定) が生成した
libspectreshell.so は、Emacs から dlopen して最初の =smp_allocator=
確保に入ると =SmpAllocator.getCpuCount= 内の未初期化レジスタ参照
(=movq (%r9), %rax= で r9=0) により segfault する。qemu-x86_64 +
lldb で特定し、LLVM バックエンド強制 (=.use_llvm = true=) で回避中。
zig を更新した際は x86_64 の Debug ビルドで ERT が通るか確認し、
直っていれば =use_llvm= 指定を外して Debug ビルドを高速化する。

2026-09-05 の再検証: 検証環境は aarch64 (=uname -m=) のため、x86_64
自前バックエンドの segfault は検証できない。zig は課題を記録した時点と
同じ 0.15.2 (=zig version=) のまま。x86_64 環境で zig を更新したときに
再検証する。

** WAIT B-2: ghostty が SDKROOT を直接使うようになったら xcode-shim を外す
対象: =nix/emacs-spectreshell.nix= (=xcodeShim=)

macOS の Nix サンドボックスには Xcode がなく、ghostty の
=pkg/apple-sdk= がビルドグラフ構築時に呼ぶ zig の
=LibCInstallation.findNative= が =xcode-select --print-path= と
=xcrun --sdk <名前> --show-sdk-path= の実行に失敗して
=DarwinSdkNotFound= panic になる (aarch64-darwin の =nix flake check=
が全滅)。$SDKROOT (apple-sdk setup hook が設定) を返すだけの
xcode-select / xcrun シムを darwin のみ nativeBuildInputs に足して
回避中。

xcbuild (xcode-select / xcrun 同梱) では代替できないことを CI で確認
済み: macosx SDK は $DEVELOPER_DIR から解決できるが、ghostty の
build.zig は darwin ターゲットだと XCFramework 用に iOS / iOS
Simulator 向けグラフも無条件に構築し (=GhosttyXCFramework.init=)、
そこで要求される iphoneos SDK は CLT 由来の Nix apple-sdk に存在
しない。シムは --sdk の値を無視して macOS SDK を返すのでここも通る
(iOS 向けステップはグラフに乗るだけで実行されない)。

ghostty の pkg/apple-sdk (または zig std) が xcrun を介さず SDKROOT
環境変数を直接尊重するようになったらシムを削除する。

2026-09-05 の再検証: ghostty upstream main (commit
492300cad104195411d12217dd22f1cd05f31376, 2026-09-04) の
=pkg/apple-sdk/build.zig= は依然として
=std.zig.LibCInstallation.findNative= 経由で xcrun を呼び、SDKROOT を
直接は見ない。zig master の =lib/std/zig/system/darwin.zig= も
=xcrun --sdk <sdk> --show-sdk-path= のままで、ピン留め中の zig 0.15.2
も同じ。条件は未達。

ただし upstream main では findNative の失敗を =catch break :darwin= で
受け、zig 同梱の Darwin ヘッダ (=libc/include/any-darwin-any=) へ
フォールバックする経路が追加されている (ピン留め中の ghostty 1.3.1 の
=pkg/apple-sdk/build.zig= には無い)。upstream main は zig 0.16 前提
(=std.Io.Writer= 等を使用) なので、ghostty を更新して zig 0.16 へ
上げた時点で、シム無しで =nix flake check= (darwin) が通るかを再検証
する。このフォールバック経路はフレームワークパスを設定しないため
libghostty-vt のビルドに足りるかは未確認 (推測)。

対象: =spectreshell.el= (=spectreshell--decorate-row=)

=just bench= の 40 区間/行 (50x200) で、1 フレーム 11.6 ms のうち

** DONE P-1: point の強制移動でスクロールバック閲覧が実質不能
対象: =spectreshell.el= (=spectreshell--move-point=)

毎 update で point と全ウィンドウの window-point をカーソル位置へ移す
ため、emacs モードで履歴閲覧中も出力のたびに引き戻されていた。

term.el と同様に、更新前の point が前回のカーソル位置だったときだけ
追従させるようにして解決した。判定は再描画の前に済ませ、バッファの
point と各ウィンドウの window-point で個別に行う。semi-char モード中は
常に追従する (d8699ff)。

** DONE P-2: font-lock 有効時に dirty 行スキップ最適化が無効化される
対象: =spectreshell.el= (=spectreshell--apply-dirty=)

=fontified= プロパティにより =equal-including-properties= が常に不一致
になり、全 dirty 行を毎回書き換えていた。

比較対象をバッファのテキストから「モジュールが最後に送ってきた生の
=(TEXT . SPANS)=」に変えて解決した。他モードが後から付けたプロパティに
左右されず、装飾を組み立てる前に短絡できる (9aa4f2a)。

** WAIT P-3: Zig ホットパスの intern / funcall 回数
対象: =src/module.zig=

キーワードシンボルを feed ごとに =intern= し直している。
=make_global_ref= での初期化時キャッシュ、=symbol-name= 文字列比較の
